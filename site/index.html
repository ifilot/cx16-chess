UNDER THE BONNET

How an 8-bit machine finds a move

01

The browser runs the actual X16 program inside a WebAssembly emulator. The chess engine itself runs as 65C02 machine code, just as it does on the 8 MHz computer.

The project keeps matching implementations in C and assembly. C makes native testing practical; assembly handles the work done at every search node on the X16. Parity tests check that both implementations visit exactly the same nodes.

I.

Represent the position

A 0x88 board stores 64 playable squares in a 128-slot array. A simple bit test catches moves that leave the board. Material, piece-square scores, and a 32-bit position hash update as moves are made and undone.

II.

Search a little deeper

Iterative deepening searches one ply deeper at a time, keeping a move from the last completed search. Principal variation search narrows the score window for later candidates. Capture search follows tactical exchanges beyond the main depth limit.

Move ordering and selective pruning focus the limited time on promising lines. Check extensions spend extra effort when a king is under attack.

III.

Evaluate & remember

The score considers material, piece placement, bishop pairs, pawn structure, and king safety. Endgame king tables help guide the king when few pieces remain.

A 16,384-entry transposition table in banked RAM remembers searched positions, bounds, and good moves. Reaching the same position through another move order can reuse that work.

At 8 MHz, the engine typically searches about 400–1,200 nodes per second. Opening and middlegame depth is often 3–6 plies; sparse endgames can go much deeper. Read the engine notes ↗

THE COMPUTER OPPONENT

Three budgets. One engine.

Difficulty changes how long the engine can think. The 30-minute game clock can shorten the budget as time runs low. These measured strength estimates come from 144 games against Stockfish 16: 48 for each level.
